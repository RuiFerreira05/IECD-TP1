================================================================================
  IECD-TP1 | XML PROTOCOL QUICK REFERENCE
================================================================================

ENVELOPE STRUCTURE (every message)
────────────────────────────────────────────────────────────────────────────────
<message type="REQUEST|RESPONSE|PUSH" id="uuid" version="1.0">
    <header>
        <action>ACTION_NAME</action>
        <session>SESSION_TOKEN</session>   <!-- omit if not authenticated -->
        <timestamp>ISO-8601</timestamp>
    </header>
    <body>
        <!-- action-specific payload -->
    </body>
</message>

  type     REQUEST  → client to server
           RESPONSE → server reply to a request (echoes request id)
           PUSH     → server-initiated, unsolicited (new id)

  id       UUID generated by the sender.
           RESPONSE always echoes back the REQUEST id.
           PUSH generates its own new UUID.


================================================================================
  AUTH
================================================================================

── REGISTER ─────────────────────────────────────────────────────────────────

  REQUEST
    <body>
        <username>alice</username>
        <password>hashed_password</password>
    </body>

  RESPONSE (success)
    <body>
        <status>OK</status>
    </body>

  RESPONSE (failure)
    <body>
        <status>ERROR</status>
        <error code="USERNAME_TAKEN">Username already exists</error>
    </body>


── LOGIN ─────────────────────────────────────────────────────────────────────

  REQUEST
    <body>
        <username>alice</username>
        <password>hashed_password</password>
    </body>

  RESPONSE (success)
    <body>
        <status>OK</status>
        <session>SESSION_TOKEN_UUID</session>
        <user>
            <id>uuid</id>
            <username>alice</username>
            <photo>base64_or_url</photo>
        </user>
    </body>

  RESPONSE (failure)
    <body>
        <status>ERROR</status>
        <error code="AUTH_FAILED">Invalid credentials</error>
    </body>


── LOGOUT ────────────────────────────────────────────────────────────────────

  REQUEST                                   (* session required)
    <body/>

  RESPONSE (success)
    <body>
        <status>OK</status>
    </body>

  USER SEARCH
================================================================================

── SEARCH_USERS ─────────────────────────────────────────────────────────────

  REQUEST
    <body>
        <query>ali</query>
    </body>

  RESPONSE (success)
    <body>
        <status>OK</status>
        <results>
            <user>
                <id>uuid</id>
                <username>alice</username>

                <photo>base64_or_url</photo>
            </user>
        </results>
    </body>

  RESPONSE (no results)
    <body>
        <status>OK</status>
        <results/>
    </body>


================================================================================
  GAME
================================================================================

── GAME_INVITE ──────────────────────────────────────────────────────────────

  REQUEST (sender → server)
    <body>
        <target-user-id>uuid</target-user-id>
    </body>

  RESPONSE (to sender)
    <body>
        <status>OK</status>
        <game-id>GAME_UUID</game-id>
    </body>

  PUSH (server → target, unsolicited)
    <body>
        <from-user-id>uuid</from-user-id>
        <from-username>alice</from-username>
        <game-id>GAME_UUID</game-id>
    </body>


── GAME_INVITE_RESPONSE ─────────────────────────────────────────────────────

  REQUEST (target → server)
    <body>
        <game-id>GAME_UUID</game-id>
        <accept>true|false</accept>
    </body>

  RESPONSE (to target)
    <body>
        <status>OK</status>
    </body>

  PUSH (server → original sender, if accepted)
    <body>
        <game-id>GAME_UUID</game-id>
        <accepted>true</accepted>
        <opponent-username>alistar</opponent-username>
    </body>

  PUSH (server → original sender, if declined)
    <body>
        <game-id>GAME_UUID</game-id>
        <accepted>false</accepted>
    </body>


── GAME_MOVE ────────────────────────────────────────────────────────────────

  REQUEST
    <body>
        <game-id>GAME_UUID</game-id>
        <move><!-- game-specific payload --></move>
    </body>

  RESPONSE (move accepted)
    <body>
        <status>OK</status>
    </body>

  RESPONSE (move rejected)
    <body>
        <status>ERROR</status>
        <error code="INVALID_MOVE">Not your turn</error>
    </body>

  PUSH (server → opponent)
    <body>
        <game-id>GAME_UUID</game-id>
        <move><!-- same payload mirrored --></move>
    </body>


── GAME_OVER ────────────────────────────────────────────────────────────────

  PUSH (server → both players)
    <body>
        <game-id>GAME_UUID</game-id>
        <winner-id>uuid</winner-id>
        <winner-username>alice</winner-username>
    </body>


================================================================================
  ERROR CODES
================================================================================

  AUTH_FAILED               Wrong username or password
  USERNAME_TAKEN            Username already in use
  SESSION_EXPIRED           Token not found or timed out
  NOT_AUTHENTICATED         Client did not provide a valid session token
  USER_NOT_FOUND            Target user does not exist
  USER_NOT_ONLINE           Target user is not currently online
  ALREADY_IN_GAME           Player is already in an active game
  INVALID_MOVE              Move rejected by game logic
  INVALID_PASSWORD          Password does not meet requirements
  UNKNOWN_ACTION            Server does not recognize the action
  INTERNAL_ERROR            Unhandled server-side exception
  MALFORMED_REQUEST         XML could not be parsed (Accompanied by UNKNOWN Action Type)
  UNEXPECTED_MESSAGE_TYPE   Client sent a RESPONSE or PUSH message type
  UNEXPECTED_MESSAGE_ACTION Client sent an unexpected action type
  OUTDATED_PROTOCOL         Client version does not match server version

================================================================================
  PROTOCOL VERSIONING
================================================================================

  version      String attribute on every message envelope.
               Current version: 1.0
               Server rejects connections where the client version does not
               match. Clients should reject responses with a mismatched
               version.
               A major version bump signals a breaking protocol change — both
               sides must be updated together.
               A minor version bump signals a backward-compatible change.

================================================================================
  SPECIAL VALUES
================================================================================

  ERROR_NO_ID    00000000-0000-0000-0000-000000000000
                 Used as the message id in RESPONSE messages where the
                 server could not extract the original request id.
                 Clients must not use this UUID for their own requests.
                 Is accompanied by an UNKNOWN action type and a MALFORMED_REQUEST error code.

================================================================================
  UUID ROLES AT A GLANCE
================================================================================

  message id       Every message carries one.
                   Client generates it for REQUEST.
                   Server echoes it on RESPONSE so client matches the reply.
                   Server generates a fresh one for PUSH.

  session token    Returned by LOGIN in <session>.
                   Client includes it in <header><session> on every
                   subsequent request.
                   Server uses it to look up the Session object and
                   identify the user.
                   Invalidated on LOGOUT or after 30 min of inactivity.
